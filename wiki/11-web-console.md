# 11 · 网页控制台

> 目录：[web/](../web/) · 启动：`python web/server.py`
> 一句话：**不用记命令行，在浏览器里看数据、跑选股、点推送、翻 K 线。**

---

## 1. 为什么是"标准库 + 一个 HTML"

这个项目的形态是"每天跑一次批处理"，不是常驻服务。为它引入 FastAPI + uvicorn + 前端构建链，
收益很小、成本很实在（依赖变多、`uv.lock` 变动、部署时要多一套东西）。

所以控制台只用了 Python 标准库的 `http.server` + 一个静态 HTML：

| 选择 | 代价 | 收益 |
|---|---|---|
| `ThreadingHTTPServer` | 没有 ASGI、没有 websocket | 零依赖、任何 Python 3.10+ 都能跑 |
| 手写 JSON 路由（6 个接口） | 没有自动文档 | 一眼看懂，改起来不用查框架 |
| 原生 JS + SVG 画 K 线 | 没有组件库 | 不需要 npm / 构建，刷新即生效 |

总计约 400 行后端 + 400 行前端。

---

## 2. 启动

```bash
python web/server.py                          # http://127.0.0.1:8123
python web/server.py --port 8123 --host 127.0.0.1
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--host` | `127.0.0.1` | **默认只监听本机**；改成 `0.0.0.0` 前先想清楚：没有鉴权 |
| `--port` | `8000` | 端口占用就换一个 |

> ⚠️ 控制台**没有登录**。它默认只绑本机，就是为了避免把"能触发飞书推送"的接口暴露到局域网。

## 3. 页面

### 3.1 总览

顶部是数据库状态卡片：行数、股票数、交易日、数据区间、库大小、**落后股票数**
（最后一根 K 线早于全表最大日的股票，等于"停牌/退市"的规模）、上次运行的耗时。

下面两张表：策略清单（标识/类名/说明/是否需要行情）与当前配置（快照窗口、并发数、
`max_picks`、最小成交额、板块涨跌停）。

### 3.2 选股

勾选策略 → 「运行选股」→ 每个策略一张表：代码、名称、收盘价、涨跌幅、成交额。
点代码会跳到「行情」页并自动画出这只票的 K 线。

结果分两块：

- **代码列表**由策略返回（已按强度排序）；
- **名称/价格/涨跌幅/成交额**由前端请求后端补全（`enrich_picks()`），
  数据来自同一份 `MarketSnapshot`，不额外查库。

页面下方有「**策略参数**」折叠区（P2-9）：每个策略暴露 2~3 个关键阈值（如 turtle 的突破窗口、
rps 的 RPS 阈值），改完直接跑一次就能看选股差异，**不需要改代码**。

* 参数值只作用在**本次请求构造的实例**上（`setattr(instance, ...)`），不污染类属性；
* 后端只接受 `TUNING` 白名单里的属性，前端传别的会被忽略；
* 只暴露少量参数——**参数越多越容易过拟合，能调不等于该调**。

「推送到飞书」是**会真的发消息**的，所以：

1. 必须点按钮（不是页面加载时自动发）；
2. 后端要求请求体里带 `"confirm": true`；
3. 只能推**当前进程里刚跑出来的结果**（`_LAST_RUN`），不能凭空构造一个列表让它发。

### 3.3 行情

输入 6 位代码 → 蜡烛图 + 成交量 + MA20，全部用 SVG 画：

- 蜡烛用当日 `open/close` 决定实体、`high/low` 决定影线，**红涨绿跌**（A 股习惯）；
- 成交量按当日最大量归一化，画在价格下方；
- MA20 是前端现算的（20 根收盘价均值），不占后端。

### 3.4 跟踪（纸面账本）

把"每天推了哪些票、后来涨没涨"变成可复盘的事实，数据来自 `pick_history` 表：

| 列 | 含义 |
|---|---|
| 笔数 / 天数 | 回看窗口内的选股笔数与覆盖的交易日 |
| 待结算 | 信号日在窗口末尾、还没有 T+1 行情（显示"待结算"） |
| h1 / h5 均值 | **T+1 开盘买、T+h 收盘卖**，已扣往返成本 0.2% |
| 胜率 | 净收益 > 0 的比例 |
| 超额 | 减去同日全市场等权收益中位数（判断选股能力，而不是看大盘） |

下方是最近 80 条留痕明细，点代码可跳到 K 线。

留痕是**幂等**的（`(run_date, strategy, symbol)` 主键）：同一天重复跑选股不会产生重复行。
`source` 列区分 `live`（当天真实跑出来的）与 `replay`（历史回放），避免把回放数据当成当时的信号。

想立刻有历史样本：

```bash
python scripts/replay_picks.py --days 120            # 用同一份 _signals 回放 120 个交易日
```

### 3.5 回测

读 `data/backtest_summary.json`（由 `scripts/backtest.py --out` 生成），
按"策略 × 样本内/样本外"展示 h1/h5 超额、年化、回撤、夏普。

```bash
python scripts/backtest.py --horizons 1,5 --top 30 \
    --start 2024-01-02 --train-end 2026-01-01 \
    --out data/backtest_summary.json
```

页面可以**触发回测**（P2-9），但走的是**后台任务**而不是同步请求：

1. 点「运行回测」→ 后端起一个子进程（`scripts/backtest.py`），立即返回 `job_id`；
2. 前端每 2 秒轮询 `/api/jobs?id=...`，把子进程日志的 tail 显示出来（下方黑色框）；
3. 任务结束（`done`）后自动加载结果。

为什么不能同步：一次回测要读几百万行、跑几十秒到几分钟，同步等待只会让浏览器超时、
用户以为页面卡死。

两个实现细节：

* 子进程必须设 `PYTHONUNBUFFERED=1`，否则 stdout 被缓冲，日志要等进程退出才有内容，
  页面上看不到任何"进度"；
* 日志写到 `logs/job<N>.log`，`/api/jobs` 只返回最后 20 行，避免把大日志塞进响应。

## 4. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 单页控制台 |
| GET | `/api/status` | 数据库规模、配置、策略清单、上次运行 |
| GET | `/api/strategies` | 策略标识与说明 |
| POST | `/api/select` | 跑选股：`{"strategies":["ma_volume"],"limit":30,"overrides":{"turtle":{"_VOL_SURGE":2.0}}}` |
| POST | `/api/push` | 推送上次结果，必须 `{"confirm": true}` |
| GET | `/api/kline?symbol=600000&limit=120` | K 线（升序返回） |
| GET | `/api/params` | 可调参数白名单（含默认值、上下限） |
| POST | `/api/backtest/start` | 起一个后台回测任务，返回 `job_id` |
| GET | `/api/jobs?id=job1` | 任务状态 + 日志 tail |
| GET | `/api/ledger?days=60` | 纸面账本：各策略业绩 + 最近留痕 |
| GET | `/api/backtest` | 回测结果 JSON |

后端把"算"和"发"分开了：`select` 只算不写，`push` 只发不重算。这样点错按钮最多是白等几秒，
不会把一份没看过的结果发到群里。

## 5. 并发与缓存

```python
_RUN_LOCK = threading.Lock()   # 选股串行化
_LAST_RUN: dict = {}           # 上次结果，供 push 使用
```

- `App` 只创建一个 `DataEngine`，**快照在进程内常驻**：第一次选股约 5 秒（读 67 万行），
  之后同一进程内的请求都是毫秒级；
- 选股用一把锁串行，避免两个请求同时把快照和中间数组顶到内存上限；
- 单个策略抛异常不影响其它策略（错误会显示在对应卡片上）。

---

## 6. 局限

1. **没有鉴权**，只适合本机用；
2. **没有历史留痕**：`_LAST_RUN` 在内存里，重启就没了。想要"每天的结果自动保存"，
   得先把选股结果落库（[09 · P3-6](09-code-review-findings.md)）；
3. **不触发同步/回填**：这两件事是分钟级甚至小时级任务，应该在命令行里跑（见 [07](07-run-and-ops.md)）；
4. 前端没有打包，因此没有 TypeScript 类型检查——后端接口改动时记得同步 `web/index.html`；
5. K 线只画日线、不复权切换（库里存的是后复权价）。
